# Desktop Imposer Pro V3.0 架构设计

## 1. 产品目标

升级现有 Desktop Imposer Pro，不重写已经稳定的生产能力。V3.0 的界面参考 Quite Imposing Plus 的工作流：左侧功能导航、中间大画布/拼版预览、右侧属性检查器、底部状态栏。

目标平台：Windows 10 / 11 x64。  
现有技术基线：Python、PySide6/Qt、PyMuPDF、Shapely，以及仓库现有 PDF/图像/打包依赖。最终依赖以恢复后的 requirements 文件和 SBOM 为准。

## 3. 分层原则

- domain：只保存页面、纸张、任务、标记和尺寸等纯业务模型，不依赖 Qt。
- application：编排导入、拼版、预检、模板和导出用例。
- engines：执行 PDF 解析、页面放置、书刊页序、双面、标记和优化算法。
- infrastructure：数据库、任务队列、日志、热文件夹及旧版工作区适配。
- ui：只负责 Qt 展示和用户交互；不得把拼版计算写在 QWidget 中。
- legacy adapter：V3.0 调用旧版稳定功能时通过适配器，不复制两套相同算法。

## 4. 主界面信息架构

1. 顶部菜单/快捷工具栏：新建、打开、保存、撤销、重做、拼版、导出。
2. 左侧导航：基本、工具、页面、标记、图像、处理、印前。
3. 中央工作区：预览、页面视图、拼版模板库；支持缩放、平移、选取、拖拽。
4. 右侧检查器：文件信息、页面尺寸、纸张尺寸、出血、标记、色彩配置、图层。
5. 底部状态栏：页数、纸张规格、拼版数量、缩放、后台任务状态。

## 5. 核心用例

- PDF 批量导入、页面缩略图、页面排序/旋转/排除。
- N-up、重复拼版、自动行列计算、手工定位。
- 骑马钉、胶装/书刊页序、双面翻转和爬移补偿。
- 包装盒/刀版、标签卷筒、卡牌等现有专用模板的兼容接入。
- 纸张、成品尺寸、边距、间距、出血、咬口及印刷方向设置。
- 裁切线、套准标、色条、页码、页面信息和自定义标记。
- PDF 导出、作业预检、项目保存/恢复、模板保存。
- 撤销/重做、后台任务、错误日志和崩溃恢复。

## 6. 印前正确性约束

- 内部几何统一使用 point（1/72 inch）或明确的毫米转换边界；禁止混用未经标注的单位。
- 页面放置变换必须显式记录平移、旋转、缩放、裁切框和出血框。
- 输出 PDF 尽量保留原始页面内容流、矢量、字体、图像和颜色空间；禁止将整页栅格化作为默认拼版方式。
- 裁切线、压痕线、套准标、色条使用独立标记层/对象，并支持开关与颜色配置。
- 双面拼版必须定义纸张翻转轴、长边/短边翻转和正反面映射，并用测试页验证。
- 书刊拼版必须用已知页数的 golden fixtures 验证每个折手的页序。
- 预检提示必须区分“检测到的问题”和“无法自动验证的项目”，不得宣称未经验证的 PDF/X、ICC、专色或叠印认证。

## 7. 性能与稳定性

- 大文件缩略图采用按需渲染、缓存和取消机制。
- PDF 渲染和批量导出放入后台任务，UI 线程不执行长耗时工作。
- 项目文件采用可迁移的 schema_version；旧项目读取必须兼容。
- 导出采用临时文件 + 原子替换；失败时保留原文件。
- 日志记录任务 ID、输入文件哈希、配置摘要、耗时和错误，不默认记录客户 PDF 内容。

## 8. 测试与发布门禁

- 单元测试：尺寸换算、可用版面、行列计算、旋转、页序、双面映射、标记坐标。
- 集成测试：PDF 导入 -> 拼版 -> PDF 导出 -> 再解析验证。
- Golden tests：固定样本对照页数、页面框、页面变换和标记位置。
- Windows CI：Python 3.12 x64、编译检查、旧版测试、V3 单测、安装包冒烟测试。
- 发布产物：安装版、便携版、SHA256、SBOM、第三方许可证声明。

## 9. 版本策略

V3.0 采用增量迁移。V2.4.x 保持可构建；新 UI 和新引擎先以 feature flag/独立入口接入，完成回归后再成为默认入口。
